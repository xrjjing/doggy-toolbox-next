# 03 启动与验证流程

## 1. 先说结论

正式进入开发后，**主启动命令应该是根目录的 `wails dev`**。

不要把它理解成：

- 先手动起 Go 后端
- 再手动起 Vue 前端
- 再自己拼桌面壳

对 Wails 项目来说，更合理的是：

- **依赖安装阶段**：分别准备 Go / npm 依赖
- **联调阶段**：在项目根目录运行 `wails dev`
- **构建阶段**：在项目根目录运行 `wails build`

---

## 2. 第一次真正开始实现时的推荐顺序

> 注意：下面这些步骤适用于你已经完成 Wails 脚手架和正式配置之后。

### Step 1：进入项目根目录

```bash
cd /Users/xrj/GoProject/doggy-toolbox-next
```

### Step 2：准备 Go 依赖

如果 `go.mod` 已建立：

```bash
go mod tidy
```

### Step 3：准备前端依赖

```bash
cd frontend
npm install
cd ..
```

### Step 4：启动开发模式

```bash
wails dev
```

这是主命令。

它的意义是：

- 读取根目录 `wails.json`
- 启动 Wails 开发模式
- 处理 Go 端重编译
- 处理前端资源变更刷新
- 打开桌面窗口进行联调

---

## 3. 如果只想看前端页面怎么办

可以单独跑：

```bash
cd frontend
npm run dev
```

但是要注意：

- 这更适合纯 UI 调整
- 如果页面依赖 Wails 绑定，就需要 mock
- 所以它不是主开发流程，只是补充手段

建议原则：

- **看布局 / 样式**：可以 `npm run dev`
- **看完整联调**：优先 `wails dev`

---

## 4. 构建验证怎么做

### 开发构建验证

```bash
wails build
```

产物通常会进入：

```text
build/bin/
```

### 这一步要验证什么

1. 是否能成功编译
2. 是否生成桌面应用产物
3. 打开后是否能进入主页面
4. 最小功能是否可用

---

## 5. 每完成一个小阶段后的验证清单

## A. 壳层验证

- [ ] 应用窗口能打开
- [ ] Vue 主页面能显示
- [ ] 左侧导航能切换
- [ ] 没有明显白屏或致命报错

## B. 前后端绑定验证

- [ ] 前端能调用一个 Go 方法
- [ ] Go 返回值能正确显示
- [ ] 异常能被前端识别并提示

## C. 单模块验证

- [ ] 输入 -> 输出闭环可用
- [ ] 边界输入不崩
- [ ] 返回结果和旧项目一致或符合预期
- [ ] 日志能定位错误

## D. 构建验证

- [ ] `wails build` 成功
- [ ] 构建产物可启动
- [ ] 启动后核心页面正常

---

## 6. 推荐的开发节奏

### 每次开始开发

1. 先 `cd` 到项目根目录
2. 如果有依赖变动，先 `go mod tidy` / `npm install`
3. 再执行 `wails dev`
4. 在桌面窗口里做联调

### 每完成一个模块

1. 手工回归这个模块
2. 再执行一次 `wails build`
3. 验证构建产物是否仍然可运行

---

## 7. 初期最小验证目标

当你完成下面 5 件事，就可以认定新项目真正起步成功：

1. `wails dev` 能启动
2. 主界面能显示
3. 有一个 Vue 页面
4. 有一个 Go 绑定方法
5. 有一个最简单工具功能可用

在这之前，不要着急迁复杂模块。
