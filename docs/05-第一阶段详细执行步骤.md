# 05 第一阶段详细执行步骤

## 1. 这份文档的目标

这份文档专门回答一个问题：

> **我要自己开始写 `doggy-toolbox-next`，第一阶段到底要做到什么程度，才算已经具备“自主开始编写”的条件？**

这里的“第一阶段”不是做业务，而是先把：

- 环境
- 启动方式
- 目录结构
- 前后端调用链
- 最小改动验证方式

全部搞明白。

只要你把这份文档走完，就应该能独立开始写第一个简单模块。

---

## 2. 第一阶段的最终目标

第一阶段结束时，你至少要能独立完成下面这些动作：

1. 知道项目根目录怎么进入
2. 知道开发时用什么命令启动
3. 知道前端代码改哪里
4. 知道 Go 代码改哪里
5. 知道前后端绑定链路在哪里
6. 知道改完以后怎么验证
7. 知道出问题时先查哪个文件、哪个命令

如果这 7 件事你都能独立做，就说明你已经可以开始自己写了。

---

## 3. 先建立正确认知

先把这 4 个概念分清楚：

### 3.1 Go

- 负责后端逻辑
- 负责桌面应用主进程
- 负责业务实现

### 3.2 Vue 3 + TypeScript

- 负责页面
- 负责交互
- 负责组件和界面状态

### 3.3 Wails

- 负责把 Go 和前端页面连起来
- 负责桌面窗口
- 负责开发模式和构建模式

### 3.4 你真正的开发主命令

开发阶段不是分别手动起很多东西，而是：

```bash
wails dev
```

这是你后面最常用的命令。

---

## 4. 当前项目里你最先该认识的 8 个文件

在开始写业务之前，先把下面这些文件看熟。

## 4.1 `main.go`

你重点看：

- 应用窗口参数
- `wails.Run(...)`
- `Bind` 里暴露了哪些 Go 对象给前端

你应该知道：

- 这是桌面程序入口
- 这里不是写业务逻辑的主场

## 4.2 `app.go`

你重点看：

- `App` 结构体
- `startup`
- `Greet`
- `GetAppInfo`

你应该知道：

- 这里是当前最小 Go 绑定示例
- 前端能调用这些方法

## 4.3 `wails.json`

你重点看：

- `frontend:install`
- `frontend:build`
- `frontend:dev:watcher`

你应该知道：

- `wails dev` / `wails build` 会读这个文件
- 这里控制 Wails 如何驱动前端工程

## 4.4 `go.mod`

你重点看：

- module 名
- Wails 版本依赖

你应该知道：

- 这是 Go 项目依赖入口

## 4.5 `frontend/package.json`

你重点看：

- `scripts`
- `dependencies`
- `devDependencies`

你应该知道：

- 前端的 `dev/build` 命令从这里来

## 4.6 `frontend/src/main.ts`

你重点看：

- Vue 应用如何挂载

你应该知道：

- 这是前端入口

## 4.7 `frontend/src/App.vue`

你重点看：

- 模板结构
- `script setup`
- `GetAppInfo / Greet` 调用

你应该知道：

- 这是当前页面主壳
- 这里最适合拿来做第一轮练手修改

## 4.8 `frontend/wailsjs/`

你重点看：

- `frontend/wailsjs/go/main/App.js`
- `frontend/wailsjs/go/main/App.d.ts`
- `frontend/wailsjs/go/models.ts`

你应该知道：

- 这些是 Wails 自动生成的前后端绑定文件
- **一般不要手改**

## 5. 第一阶段实际执行步骤

下面按真正可执行顺序来。

## Step 1：确认项目能进入

```bash
cd /Users/xrj/GoProject/doggy-toolbox-next
pwd
```

你应该看到：

- 当前目录就是 `doggy-toolbox-next`

如果连目录都进错，后面所有命令都会跑偏。

---

## Step 2：确认核心工具可用

执行：

```bash
go version
node -v
npm -v
wails version
```

当前这台机器最近一次已验证通过的参考值：

- Go：`go1.24.3`
- Node：`v23.11.0`
- npm：`11.6.2`
- Wails：`v2.12.0`

你不需要和这个版本一模一样，但至少要：

- 命令能执行
- 没有 `command not found`

---

## Step 3：确认项目依赖是完整的

执行：

```bash
go mod tidy
cd frontend
npm install
cd ..
```

你应该理解：

- `go mod tidy`：补 Go 依赖
- `npm install`：补前端依赖

这一步做完，才适合正式进入开发。

---

## Step 4：先用 `wails dev` 跑起来

执行：

```bash
wails dev
```

你应该看到：

- Wails 启动开发模式
- 打开桌面窗口
- 页面里有欢迎信息
- 有一个输入框和按钮

如果这一步失败，先不要写业务，先把启动问题解决。

---

## Step 5：做第一轮“只改前端”的练习

目标：确认你已经知道**改 Vue 页面应该改哪里**。

### 建议练习

修改文件：

```text
frontend/src/App.vue
```

只改这两类内容之一：

1. 页面标题文案
2. 左侧导航文案

例如把：

- `欢迎页`
- `重写白板 · 独立新仓库`

改成你自己的文字。

### 你要观察什么

- 保存后，页面是否自动刷新
- 改动是否立即显示

### 这一轮你要确认的结论

> 我已经知道页面文字和布局主要改 `frontend/src/App.vue`

---

## Step 6：做第二轮“只改 Go”的练习

目标：确认你已经知道**改 Go 绑定方法应该改哪里**。

修改文件：

```text
app.go
```

### 建议练习

改 `Greet` 方法返回内容，比如把：

```go
Hello xxx, doggy-toolbox-next is ready.
```

改成你自己的提示语。

### 然后怎么验证

1. 保持 `wails dev` 运行
2. 回到桌面窗口
3. 输入一个名字
4. 点击按钮
5. 看返回结果是否变了

### 这一轮你要确认的结论

> 我已经知道后端绑定逻辑当前主要改 `app.go`

---

## Step 7：做第三轮“新增一个最小 Go 方法”的练习

目标：确认你已经知道**前后端绑定链路是怎么接上的**。

### 第一步：在 `app.go` 里增加一个方法

例如新增：

```go
func (a *App) Ping() string {
    return "pong"
}
```

### 第二步：重新跑一次开发命令

如果当前窗口状态不稳定，直接重新执行：

```bash
wails dev
```

### 第三步：看自动生成的绑定文件

你去看：

```text
frontend/wailsjs/go/main/App.js
frontend/wailsjs/go/main/App.d.ts
```

观察点：

- 有没有新增 `Ping`

### 第四步：在 `frontend/src/App.vue` 中调用它

做一个按钮或在 `onMounted` 里调用它都行。

### 这一轮你要确认的结论

> 我已经理解：Go 方法 -> Wails 生成绑定 -> Vue 调用，这条链路是通的

---

## Step 8：把目录职责说清楚

这一步看起来不像写代码，但非常重要。

在开始迁第一个模块前，你必须能自己说出：

### 根目录

- `main.go`：启动入口
- `app.go`：当前最小绑定层示例
- `wails.json`：Wails 配置
- `go.mod`：Go 依赖

### `frontend/`

- 放 Vue 代码
- `src/` 是主战场
- `wailsjs/` 是自动生成绑定

### `internal/`

- 将来放真正业务逻辑
- 这是你后续学习 Go 的核心区域

### `build/`

- 打包资源和构建产物相关

如果你现在还说不清，先别急着写模块。

## 6. 第一阶段结束后，下一步该做什么

不要马上迁复杂模块。

最合理的下一步是：

1. 新建一个简单工具页面
2. 做一个最小输入 / 输出表单
3. 在 Go 里写一个最简单业务函数
4. 接通 Vue 调用
5. 做一次 `wails build`

建议第一个练手模块优先选：

- Base64
- URL 编解码
- JSON 格式化

这三个都比 CRUD、AI 聊天、节点转换更适合第一块练手。

---

## 7. 第一阶段常见误区

### 误区 1：一上来就想迁完整业务

这样很容易把学习和重构搅在一起。

### 误区 2：把所有 Go 逻辑都继续写在 `app.go`

`app.go` 只是当前最小绑定示例，不应该变成你的永久业务中心。

### 误区 3：把 `frontend/wailsjs/` 当成手写代码目录

这里主要是自动生成文件，不是你主要写业务的地方。

### 误区 4：还没跑通 `wails dev` 就开始写页面

先把启动闭环跑通，再写功能。

---

## 8. 最后一句话

第一阶段不是“学完所有概念”，而是：

> **把项目启动、改动、联调、定位、验证这条最小闭环跑通。**

当你能独立完成这条闭环时，你就已经可以开始自己写了。
