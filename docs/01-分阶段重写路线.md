# 01 分阶段重写路线

## 总原则

- **不动旧项目**：旧项目继续可用
- **先搭壳，再迁业务**：先跑通技术栈，再迁功能
- **先简单，后复杂**：先迁无状态工具，再迁复杂页面
- **每阶段都可验证**：没有验证闭环就不进入下一阶段

---

## Phase 0：基线确认

### 目标

把技术路线和边界定下来，避免后面反复返工。

### 要做的事

1. 确认新项目名称：`doggy-toolbox-next`
2. 确认新技术栈：Go + Wails + Vue 3 + TypeScript
3. 确认本阶段不动旧项目
4. 确认独立远端仓库：`doggy-toolbox-next`
5. 确认第一批迁移目标只选简单模块

### 完成标准

- 技术路线不再摇摆
- 文档中已有统一说法
- 新项目目录和分支已建立

---

## Phase 1：工具链与脚手架

### 目标

把项目真正“跑起来”。

> 如果你准备自己动手写，而不是继续让 AI 代写，请直接配合阅读：
>
> - `docs/05-第一阶段详细执行步骤.md`

### 要做的事

1. 安装 Wails CLI
2. 确认 Go / Node / npm / PATH 正常
3. 生成一份 Wails 官方 `vue-ts` 模板做参考
4. 明确正式仓库中根目录、`frontend/`、`internal/`、`build/` 的分工
5. 准备 `.gitignore`、README、基础 docs

### 验证标准

- `wails version` 可执行
- `wails doctor` 无关键阻塞错误
- 能明确说出每个核心目录职责
- 能独立完成一次“改前端文案 -> 改 Go 返回值 -> 重新联调 -> 看到结果”

---

## Phase 2：最小可运行壳

### 目标

先做一个能打开的桌面应用，不碰业务复杂度。

### 要做的事

1. 建立 Wails 主入口
2. 建立 Vue 前端主入口
3. 做最简单布局：
   - 左侧导航
   - 主内容区
   - 顶部标题区
4. 增加一个欢迎页 / 关于页
5. 做一个最小 Go 绑定方法，例如：
   - `GetAppInfo()`
   - `Ping()`
6. 前端调用这个 Go 方法并显示结果

### 验证标准

- `wails dev` 能打开桌面窗口
- Vue 页面能正常渲染
- 前端能调用 Go 方法并拿到返回值
- 改前端代码能热更新
- 改 Go 代码能重编译并重启

---

## Phase 3：工程骨架成型

### 目标

在还没迁复杂业务之前，把“以后不会乱”的结构先搭好。

### 要做的事

1. 明确前端分层：
   - `views/`
   - `components/`
   - `stores/`
   - `services/`
   - `types/`
2. 明确后端分层：
   - `app/` 绑定层
   - `internal/` 业务层
   - `internal/storage/`
   - `internal/settings/`
   - `internal/tools/`
3. 统一错误处理方式
4. 统一日志输出方式
5. 决定本地数据保存策略（SQLite / JSON / 配置文件）

### 验证标准

- 目录职责清晰
- 不再把逻辑堆在 `main.go`
- 不再把所有前端逻辑写在单个页面文件里

---

## Phase 4：迁移第一批简单工具

### 目标

先把最适合练手、最容易闭环的小工具迁进来。

### 建议优先级

1. Base64 编解码
2. URL 编解码
3. 时间格式转换
4. JSON 格式化
5. 哈希计算

### 为什么先迁这些

- UI 简单
- 状态少
- 前后端边界清楚
- 容易验证对错
- 很适合熟悉 Vue 组件和 Go 服务调用

### 每个工具的迁移动作

1. 先列旧项目输入 / 输出 / 校验规则
2. 在 Go 里实现业务逻辑
3. 在 Vue 里实现页面与表单
4. 接通前后端调用
5. 做手工回归验证

### 验证标准

- 输入输出与旧项目一致
- 错误提示清晰
- 代码结构符合新的目录规范

---

## Phase 5：迁移 CRUD 页面

### 目标

开始迁移真正带状态、带存储、带列表管理的模块。

### 推荐顺序

1. 设置页
2. 命令管理
3. 密码管理
4. HTTP 请求集合

### 要做的事

1. 先设计数据模型
2. 再设计本地持久化
3. 再设计页面状态管理
4. 再做新增 / 编辑 / 删除 / 查询
5. 最后补排序、搜索、过滤

### 验证标准

- 数据能持久化
- 重启应用后状态可恢复
- 列表与表单操作闭环完整

---

## Phase 6：迁移复杂能力

### 目标

最后才处理复杂链路与高维护成本模块。

### 复杂模块举例

- AI 聊天
- Provider 管理
- 流式输出
- 节点转换
- 更复杂的导入导出

### 原则

- 先画链路图，再动手
- 先做最小闭环，再做增强
- 复杂模块一律拆服务，不要直接堆到绑定层

### 验证标准

- 至少能跑通一条最小链路
- 错误处理与日志清晰
- 不会因为一个复杂模块拖垮整个项目结构

---

## Phase 7：打包与发布

### 目标

等前面 1~6 阶段稳定后，再考虑对外使用。

### 要做的事

1. 自定义图标与应用信息
2. 完善 `build/` 平台资源
3. 运行 `wails build`
4. 产出 macOS 可运行包
5. 写安装与使用说明
6. 做最基本发布检查

### 验证标准

- 构建产物可运行
- 启动无明显报错
- 核心功能可用
- 文档足够让他人上手

---

## 建议节奏

### 本周只做这些就够

1. 跑通 Wails + Vue 3 + TS
2. 完成最小桌面壳
3. 做一个最简单工具页

只要这三件事完成，你就已经真正开始了。
