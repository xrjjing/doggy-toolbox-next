# 02 目录结构与配置说明

## 1. Wails 官方默认布局

根据 Wails 官方文档，项目默认结构大致如下：

```text
.
├── build/
├── frontend/
├── go.mod
├── go.sum
├── main.go
└── wails.json
```

官方含义：

- `main.go`：Go 主入口
- `frontend/`：前端项目
- `build/`：构建和打包资源目录
- `wails.json`：Wails 项目配置
- `go.mod/go.sum`：Go 依赖管理

---

## 3. 为什么这样拆

### `main.go`

负责：

- 组装 Wails 应用
- 注入绑定对象
- 设置窗口参数
- 调用 `wails.Run()`

不建议负责：

- 具体业务逻辑
- 数据库逻辑
- 各工具实现

### `app/`

负责：

- 给前端暴露可调用接口
- 做参数适配、错误包装
- 调用 `internal/` 中服务

### `internal/`

负责：

- 真正的 Go 业务逻辑
- 存储
- 配置
- 工具实现
- AI / 导入导出 / 数据转换等复杂能力

### `frontend/`

负责：

- 页面展示
- 用户交互
- 状态管理
- 前端路由
- 调用 Wails 绑定

### `build/`

负责：

- 图标
- 平台打包资源
- 构建产物相关配置

## 4. 核心配置文件怎么放

## `wails.json`

位置：**项目根目录**

作用：

- Wails 项目配置总入口
- 控制前端目录、安装命令、构建命令、build 目录等

常见关键字段：

- `frontend:dir`
- `frontend:install`
- `frontend:build`
- `build:dir`
- `assetdir`
- `info`

说明：

- Wails CLI 在 `wails dev` / `wails build` 时会读取它
- 如果字段不配清楚，前端构建和联调容易混乱

## `go.mod`

位置：**项目根目录**

作用：

- 定义 Go 模块名
- 记录 Go 依赖版本

建议：

- 正式开始写 Go 代码前尽早初始化
- 不要把所有代码都放 root package

## `frontend/package.json`

位置：`frontend/package.json`

作用：

- 定义前端依赖
- 定义 `dev` / `build` 等 npm scripts

## `frontend/vite.config.ts`

位置：`frontend/vite.config.ts`

作用：

- Vite 构建配置
- 别名配置
- 插件配置

## `frontend/tsconfig.json`

位置：`frontend/tsconfig.json`

作用：

- TypeScript 编译规则
- 严格程度控制

## 5. 前端建议目录职责

### `src/views/`

页面级组件，一个路由对应一个 view。

### `src/components/`

复用组件，例如：

- 页面卡片
- 通用按钮
- 表单片段
- 弹窗

### `src/services/`

前端访问后端的统一入口，例如：

- `appService.ts`
- `toolService.ts`
- `settingsService.ts`

这里不要直接散落调用，尽量统一封装。

### `src/stores/`

放 Pinia store，用于保存跨页面状态。

### `src/types/`

放前端共享类型定义，提升可读性。

---

## 6. 后端建议目录职责

### `internal/tools/`

每个工具一个子目录，例如：

- `internal/tools/base64/`
- `internal/tools/jsonfmt/`
- `internal/tools/timeutil/`

### `internal/storage/`

放：

- SQLite
- 文件存储
- 仓储层
- 本地配置读写

### `internal/settings/`

放全局配置读取与保存逻辑。

### `internal/common/`

放真正通用的工具，不要什么都往这里塞。

---

## 7. 一个重要原则

### 先把目录放对，再开始写业务

这样后面每加一个模块，都会比较稳。

否则很容易出现：

- Go 逻辑堆在 `main.go`
- Vue 页面直接写一坨逻辑
- 前后端调用散落 everywhere
- 后期很难审核 AI 生成代码
